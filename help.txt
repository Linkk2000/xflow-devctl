Issue (GitHub/Gitee):
  devctl issue create <title> [--body B] [--body-file F] [--labels a,b]
  devctl issue list [--state open|closed|all] [--limit N]
  devctl issue show <number>
  devctl issue comment <number> [--body B] [--body-file F]
  devctl issue close <number>

Note:
  Use --body-file for multi-line or shell-sensitive Markdown bodies. --body is for simple single-line text only.
  In academic Python mode, GitHub issue create/list/show/comment/close are
  handled by the Python core through GITHUB_TOKEN. issue create, comment, and
  close require the local approval gate before remote writes. issue comment
  rejects inline --body in academic mode; use --body-file or
  .xflow/issues/issue-<id>/comment-draft.md.

MR:
  devctl git mr --title T [--body B | --body-file F] [--issue N]
  devctl git pr-get <number>

  Use --body-file for MR descriptions containing Markdown sections, code
  fences, JSON, shell snippets, backticks, or multiple lines.
  In academic Python mode, git mr creates a GitHub PR after local approval
  and requires --body-file or the default issue MR draft. git pr-get reads a
  GitHub PR without a local approval gate because it performs no remote write.

Preflight:
  devctl preflight
      Validate Python 3.10+ runtime, repo root, tool root, and product-line context.

Academic checks:
  devctl check academic-issue --issue N [--file F]
  devctl check tdd-result --issue N [--file F]
  devctl check claude-package --issue N [--file F]
  devctl check academic-mr --issue N [--file F]
  devctl check local-review --issue N --file F
  devctl check scope --issue N [--mode review-only]
  devctl check current-task [--issue N]
  devctl check submodule-hygiene

  These checks validate local Academic XFlow templates before remote writes.
  local-review also compares Approved SHA256 with the current file hash.
  scope verifies changed files against the task mode allowlist. In review-only
  mode, default allowed paths are issue-local evidence directories and
  .xflow/local; extend with .xflow/scope-policy.json after human review.
  current-task detects stale .xflow/current-task.md state, such as a local PR
  number existing while the task file still forbids push or PR creation.
  submodule-hygiene verifies that .xflow/ops/devctl and .xflow/ops/workflow are free of
  tracked changes and common byproducts, and that .gitmodules uses
  ignore = untracked for both tool submodules.

Claude:
  devctl claude doctor
  devctl claude skills
  devctl claude run --issue N [--file F] [--output F] [--dry-run]

  doctor checks whether the local Claude CLI is visible and whether
  AcademicForge is registered in the Claude config. Missing AcademicForge is
  reported with a reviewable command; no installation is performed.

  skills lists the verified AcademicForge command catalog that can be used in
  Claude task package Invocation fields.

  Validate a Claude task package, call the local Claude CLI with the package
  content, and write the result to the package Output File. Set
  DEVCTL_CLAUDE_COMMAND to override the command prefix. The default command is
  `claude -p <task-package-content>`.

AI rule entrypoints:
  devctl rules list
  devctl rules sync <id> [--force]
  devctl rules sync --all [--force]

  Read .xflow/ops/workflow/templates/ai-rules.json and copy the selected
  AI-client rule file into the paper repository root. This lets a repository
  initialized by one tool add another tool's entrypoint later, for example
  adding Cursor's .cursorrules after Codex created AGENTS.md. Existing edited
  files are not overwritten unless --force is used after human review.

Migration helpers:
  devctl migrate inspect
  devctl migrate wrappers

  inspect reports whether the paper repository still uses the legacy _ops
  layout, HTTPS submodule URLs, missing .xflow/ops paths, or missing
  ignore = untracked. wrappers writes v2 root devctl/devctl.ps1 wrappers that
  point to .xflow/ops/devctl. The Windows wrapper calls Python directly and
  does not call bash, WSL, Claude, or any installer.

Local approval:
  devctl approval prepare --issue N --action ACTION --file F [--command C] [--force]

  Pre-fill the active local review file with mechanical fields: approved file,
  lowercase SHA256, timestamp, action, and suggested command. The generated file
  keeps Approved: no; the human reviewer must change it to Approved: yes after
  inspecting the exact artifact and command.

App:
  devctl app start-frontend [--port PORT] [--foreground]
      Start the frontend dev server with a WSL-safe Vite config.
  devctl app stop-frontend
      Stop the recorded frontend dev server process.
  devctl app status
      Show recorded process, HTTP health, and log location.

Development environment:
  devctl run [--backend PATH]
      Start backend and frontend, then open the browser.
      Environment variable: XFLOW_BACKEND_ROOT (default: ../xflow-server)

Configuration:
  GITEE_ENV_FILE     Token file path (default: ~/gitee.env.local)
  GITHUB_TOKEN       GitHub personal access token
  GITEE_TOKEN        Gitee personal access token
  XFLOW_PLATFORM     Platform override (github|gitee; default: detect from remote)
  DEVCTL_BASE_BRANCH Base branch override (default: auto-detect master/main)
  DEVCTL_BRANCH_PREFIX Branch prefix (default: feature)

Token file example (~/gitee.env.local):
  GITHUB_TOKEN=your_github_token
  GITEE_TOKEN=your_gitee_token
